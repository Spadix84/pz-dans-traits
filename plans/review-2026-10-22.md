# Code review and bug report, 2026-10-22: the October batch

Scope: everything uncommitted on `master` since 24113f7, that is the whole post-1.3.0 batch: 80 modified files and 15 new ones, 4,100 lines added. New systems: Fitness overhaul (Fitness, FitnessData, FitnessActions, FitnessUI, stretch action), Cooking overhaul, Hot water bottle (+ heat action), cyclobenzaprine (Relaxant), Sensory Issues (+ stim action), ADHD. Changed systems: Laundry (washer-watch toggle hooks, dryer sheets), Sleep (sleeping in clothes), Diabetes (animal insulin, syringes, sandbox loot), AgeTraits (Bad Back, 20s pricing), Migraine (migSight fallback), Bathing, Moodles (7 new specs), Distributions, Util; Base Unloader (Off limits, "same categories as last", item-menu tagging) on top of the committed resolver.

Baseline: `python tests/run_tests.py` 88/88, `lint_kahlua.py` clean, `check_api.py` 0 problems. Cross-checks run over the whole tree: every `DanTraits.X` item type named in Lua exists in `scripts/DanTraits.txt`; every translation key, including the 18 dynamically built prefixes, resolves in EN; every `DanTraits_AddHook` name is fired somewhere (the six that look dead are the delta pipeline's); the vanilla signatures the new wrappers rely on (`adjustMaxTime` in `create()`, `ISFitnessUI:addExerciseToList(type, data)`, `ISAddItemInRecipe.baseItem`, `ISEatFoodAction:update`, `ISFitnessAction.exercise/exeDataType`) match the installed B42.

Five reviewers read the files by cluster. Findings marked **confirmed** were traced in the working tree and, where it mattered, in the installed game's Lua and scripts. "Plausible" means the code path is real but the game-side fact was not re-derived.

## Verdict

The plumbing is sound: no Kahlua-illegal syntax, no wrapped `new()`, every wrap is tag-idempotent across the load-time + `OnGameStart` double call, nothing new runs per tick that should run per minute, and the trait-gated `DanTraits_Every` registrations (ADHD, Sensory) have their `clear` functions. The bugs are of three kinds. One is a plain data error that guts a feature (Sleep's slot table). A group are seams between two new systems, or a new system and an old clock, where one side's assumption about timing or ownership is not the other's (the hot water bottle and Vitality, ADHD's pipeline and other systems' boredom floors, Sensory's tier notices, Base Unloader's self-source loop). The third kind is multiplayer: Fitness's rep path, Cooking's cook stamp, Laundry's toggle hooks and Base Unloader's store are all written for the single-player side of the action lifecycle. They work in SP and split-screen, which is what the mod promises, but the Workshop has MP players (the 1.2.1 hotfix came from one), so A3 collects them for `plans/multiplayer.md`.

Nothing here is play-tested yet; the confirmed items in A1 are what to fix before the first session.

**Status 2026-10-22 (later the same day):** A1.1 to A1.8 are fixed, each with the test named in C (`DanTraits_BodyLocation` in Util for A1.1; the bottle keeps its count through `nightGap` + 10 for A1.2; `floorsThisMinute` honoured for A1.3; `siTold` follows the tier down and `siPeak` keeps the calm line for A1.4; `giveUp`/`stall` in the Base Unloader run loop for A1.5; a client-side `animEvent` wrap and `dtRepn` for A1.6; `warmthLeft(item, rate, peek)` for A1.7; `sw` cleared off the body for A1.8). Suite 88/88 green, deployed, unplayed.

A2 the same evening: 9, 11, 12 (rule now after laundry and garbage, before contains; a rule for shirts is for clean ones), 13 (kind-based stages skip hidden containers, tags still count), 14, 15 (`DRIFT_MIN_TIME` 200), 17 (pending reps carry the exercise key, cleared on Cancel), 18, 19, 20, 21 (drizzle at 0.05, the bath via `DanTraits_BathingWet`), 22, 23, 24 (category rules dropped from `destinationOf` and purged by `BU.store`), 25 (forgotten on game start, noted only when a tag is ticked on) are done, each with a test. 10 decided 2026-10-23: a jog or carry minute counts half toward hard minutes (`FIT_HARD_HALF`), built and tested; 16 (the worn-thin dead zone) left as it is on purpose. ## A. Bugs, ranked

### A1. Fix before play-testing

1. **Sleeping in clothes: 34 of the 72 slot keys never match a real garment.** `DanTraits_Sleep.lua:96-116` keys `CL_SLOTS` with underscored names (`sweater_hat`, `full_suit`, `jacket_hat`, `torso_extra_vest`, `mask_full`, `hands_left`...) and `:160` looks up `CL_SLOTS[loc:lower():gsub("^.*:", "")]`. B42's ids are `base:sweaterhat`, `base:fullsuit` and so on, no underscores. Against the installed scripts (109 distinct ids): 38 keys match, 27 would match with the underscores removed, 7 (`torso1`, `body_costume`, `full_robe`, `fore_arm_left/right`, `jacket_hat_bulky`, `full_suit_head_scba`) exist in no vanilla script at all. So a hoodie, a suit or hooded jacket, a vest, body armour, a hazmat suit, holsters, fanny packs, masks, full hats and gloves-by-side all cost nothing in bed. Laundry hit the same thing on 2026-10-20 and now does `FULL[(k:gsub("_", ""))]` (`DanTraits_Laundry.lua:135-141`); Laundry's own lists also carry four of the seven phantom ids. Fix: one `DanTraits_BodyLocation(item)` in Util (lower-case, prefix stripped, underscores dropped) used by both, keys written the same way, and a Sleep test that dresses with real ids (`sweaterhat`, `fullsuit`, `torsoextravest`, `maskfull`). `test_sleep.lua` passes only because `dress()` uses the mod's own spellings. **Confirmed.**

2. **The warm-bottle night bonus can never land.** `DanTraits_HotWaterBottle.lua:239-243` counts waking minutes after a night with the bottle and drops `hwbNightMin` after `HWB_NIGHT_KEEP = 10`. Vitality scores the night, and runs the `nightQuality` hook the bottle subscribes to, only when `vitAwakeMin >= DanTraits_NIGHT.gapMin = 60` (`DanTraits_Vitality.lua:323`, `DanTraits_Util.lua:143`). Hot water bottle runs at order 20, so the count is gone 50 minutes before anyone asks for it. `test_hotwaterbottle.lua:219` passes because it calls `DanTraits_RunHooks("nightQuality")` by hand straight after waking. Fix: keep the count until the hook consumes it (it already clears it there), dropping it only after `gapMin` plus a margin, or on the next sleep. **Confirmed.**

3. **ADHD's boredom multiplier scales other systems' floors, and hyperfocus erases them.** `DanTraits_ADHD.lua:147-152` returns `delta * 1.5` for every rise the pipeline sees and `0` while hyperfocused. The pipeline sees every rise since its last write, which includes `DanTraits_FloorUp(BOREDOM)` from Sensory's shutdown (`DanTraits_Sensory.lua:580`, floor 50) and Endorphin Junkie's Restless (`DanTraits_Fitness.lua:802`, floor 30), and Exercise Averse's `StatAdd` (`:615`). Util sets `d.floorsThisMinute.boredomRise` for exactly this and Iron Gut checks it; ADHD does not. So a shutdown's ramp runs at 2.5 a minute and overshoots, and while hyperfocused the pipeline writes boredom back to `last` every minute so those floors never move at all. Fix: `if d.floorsThisMinute and d.floorsThisMinute.boredomRise then return nil end` at the top of the hook (and decide whether `StatAdd` rises should set the flag too; today only `FloorUp` does). **Confirmed.**

4. **Sensory tier notices stop after the first overload.** `DanTraits_Sensory.lua:536-559` sets `siTold = 3` on an overload and only clears it at tier 0. A character who then hovers between tiers 1 and 2 for the rest of the day never hears "Overwhelmed" or a cause line again (`tier == 2 and siTold < 2` is false). Fix: when `tier < was`, set `siTold = tier`. Test 5 only checks the walk down to 0. **Confirmed.**

5. **Base Unloader: "put away what I'm carrying" can spin forever.** `BaseUnloader_Run.lua:250-259, 282-285`: when `walkToContainer` fails or nothing at the stop passes `hasRoomFor`, the items leave `plan.carried`, `pending` is set and the step returns without queuing a marker, so `afterStep`'s `noProgress` counter (`:383-388`) never runs. With a vehicle source the items stay in the bag and the run ends when the trunk empties. With `src.kind == "self"`, `loadStep` (`:297-305`) re-reads everything carried, the resolver sends the same items to the same container, and the cycle repeats every tick with `walkToContainer` clearing the action queue each time: the character freezes. Fix: count these empty steps in `noProgress`, or keep a per-run `refused` set of (item, container) that `BU.route` excludes. **Confirmed.**

6. **Fitness in multiplayer: reps are counted on the server, so nothing happens on the client.** Vanilla `ISFitnessAction:animEvent` (`shared/TimedActions/ISFitnessAction.lua:158-169`) calls `exeLooped()` only when `isServer()` or single-player; the client runs the `else` branch. `DanTraits_FitnessActions.lua:67-83` wraps `exeLooped` to set `DanTraits_FitRep` and call `DanTraits_FitOnRep`, and `:75-81` is also where a set of N reps stops itself (`self.dtReps`, set client-side in the `start` wrap at `:87-96`). On a server: no load, no session, no Pumped, no plan progress, the XP factor never applies (`DanTraits_FitRep` is only ever set server-side), while the server's copy of the player accumulates load, rolls strains and calls `notify`; and a "10 reps" set is a 240-minute workout (`FitnessUI.lua:342-353` writes `SET_MINUTES` into the time box) unless cancelled. Fix: wrap `animEvent` and count `event == "ActiveAnimLooped" and self:isStarted()` when `not isServer()`; keep the `exeLooped` wrap for SP. **Confirmed** against vanilla; SP is unaffected.

7. **Hot water bottle: any look at the bottle re-stamps its clock at the indoor rate.** `warmthLeft(item, rate)` (`DanTraits_HotWaterBottle.lua:91-101`) writes `dtHwbLeft, dtHwbAt` on every call. `DanTraits_HwbStage` calls it with rate 1, and the client tooltip (`HotWaterBottleClient.lua:70`) and `ISDanTraitsHeatAction:isValid` (`:27`, every tick while holding it) call that. In the frost (rate 2) or in bed (rate 2/3) the per-minute rate in `carriedBottles` (`:178`) only governs the minutes nobody looked. Also per-tick mod-data writes while holding. Fix: a read-only path for the stage (compute from the stored fields without writing), and let only the minute pass advance the clock. **Confirmed.**

8. **Sweat-damp garments taken off never go musty.** `DanTraits_Laundry.lua:303-306`: `sight()` skips the damp clock while `s.sw` is set, and `sw` is cleared only below `DRY_AT` on the body (`:375`) or by a wash. A shirt that went damp from sweat and is then put in a bag keeps `sw`, so `dh` never accumulates and `mustyIn` is nil for good. Fix: clear `sw` in `sight()` when the garment is not worn. Plausible.

### A2. Fix soon

9. **`DanTraits_SensoryOverload` fires from merely Overwhelmed.** `DanTraits_Sensory.lua:658-662` returns `over(load, 60, 100)`, so Migraine's trigger (`DanTraits_Migraine.lua:339`, weight 1.5) is already 0.5 at load 80 with no overload, and stays on during the 50-90 hold. The header and Migraine both say "an overload". Either key it on `siTier == 3` or rename and re-weight. **Confirmed** (semantics).

10. **Carrying and jogging are "hard" training.** `hardMinutes` (`DanTraits_Fitness.lua:209-218`) excludes only mobility and work. `dtcarry` logs whenever HEAVY_LOAD >= 1 while moving (`:417-419`), which is most looting; 20 such minutes break a rest day and knock the plan off, and ~100 a day for seven days is Overtrained (`:664-669, 768-772`) with its night and endurance penalties, for walking home encumbered. A Natural Runner's jog logs double (`:537-540`). Decide whether carry/jog are hard; if not, weight them or exclude them. Plausible, a balance call.

11. **`clearFitness` is partial.** `:713-718` leaves `ftLog, ftLast, ftDay, ftPlan, ftPlanStart, ftHardStreak, ftRestStreak, ftWeeks, ftGap, ftLastPump, ftPumpMax`. Sandbox off for a week, then on: `rollDays` (`:700-709`) replays up to eight stale days with notices and the hard streak continues. The header's key list also omits `ftMissDay, ftBackDay, ftPumpMax, ftLastPump, ftRestless, ftTrainingNow`. Plausible.

12. **Base Unloader: an explicit rule loses to inference.** `BaseUnloader_Core.lua:340-351`: `contains` and `freezer` run before `rule`. Drag Hammer onto Locker and it is ignored for as long as any shown container already holds a hammer (every new hammer joins that one, so the rule can never win); "Eggs to the counter" loses to the fridge. The window counts the item as assigned (`BaseUnloader_UI.lua:742`) while the run puts it elsewhere. If intended, say so in the Workshop text; otherwise move `rule` above `contains`. Plausible, design call.

13. **Base Unloader: "hidden containers are never inferred into" holds only for `contains`, `category` and `nearest`.** `Core.lua:320` (laundry), `:325` (bins by kind), `:343` (freezer) and `:352` (tag) search `open`, which includes hidden rows: a hidden fridge still takes all fresh food. Decide per stage; freezer and bin-by-kind should at least use `shown`. Plausible.

14. **Base Unloader: resume loses the vehicle part.** `BaseUnloader_Scan.lua:493-508` saves no part id, so a run started on a glove box or seat resumes on the trunk. Save `vpart:getId()`. Plausible.

15. **ADHD drift-off samples whatever is at the head of the queue, and `forceStop` clears the whole queue.** `DanTraits_ADHD.lua:255-262, 181-187`: once a minute against the current action regardless of length, so a one-second transfer in a 40-item loot queue is as likely a victim as a 20-minute craft, and when it drifts the other 39 transfers are dropped. Exempt actions under a few seconds (`action.maxTime`) or roll only past `getJobDelta() > 0.1`. Plausible.

16. **Sensory: worn-thin can pin the load at 100 with no drain.** `:518-533`: at toll 3 the touch channel alone (wool jumper 0.5 + helmet 0.3 + wet 0.5, clamped at 1) gives target 100 and drain 0; `DRAIN_BLOCK` is not scaled by the toll while the target is, so the dead zone widens with each overload. Balance call.

17. **Fitness: stale pending reps.** `DanTraits_FitPendingReps[player]` (`FitnessUI.lua:344`) survives if the queued action never starts (get-up or unequip actions cancelled); the next `ISFitnessAction`, from any window, inherits it. Clear on Cancel and when `start` sees a different `exeDataType`. Plausible.

18. **Fitness: shared definition mutated per window.** `FitnessUI.lua:287-293, 337` write `data.item` and `data.name` on the shared `FitnessExercises.exercisesType` entry; in split-screen the second player's pick renames and re-targets the first's. Plausible.

19. **Fitness: "last seven days" is eight.** `onPlan` loops `today - 7 .. today` (`:256`), pruning keeps nine (`:708`), the window draws seven (`FitnessUI.lua:228`). Pick one. Plausible.

20. **Cooking: Fuelled runs with Fitness off.** `startFuel` (`:241`) is not gated on `fitOn()`, so the Good Meal moodle promises "training pays more" when the XP hook can never fire. Cosmetic.

21. **Laundry `bodyDry` calls any non-rain rise sweat.** `:369`: `rainedOn` needs outside and intensity >= 0.1, so drizzle, a doorway, or the mod's own bath (`DanTraits_BathingWet` exists now) mark a garment as sweat with no damp clock. Plausible.

22. **Bad Back writes `bbMoodle = 0` into every character's mod data every minute** (`DanTraits_AgeTraits.lua:~297`); the other cleared fields are nil and the Moodles spec already returns 0 without the trait. Trivial.

23. **`DanTraits_DropHeld` says "dropped" when nothing left the inventory** (`DanTraits_Util.lua:616-624`, the vehicle-with-no-seat-room branch). Tested as intended; the notice text should not say the item fell.

24. **Base Unloader: stale `cat:` rules.** Nothing sets one any more and the resolver never reads them, but `BU.suggest` still honours them (`Core.lua:91, 503`), so an old save's `cat:Food` rule silently suppresses every Food suggestion, and "Unassign the whole category" (`UI.lua:189-191`) is offered for a feature that no longer exists.

25. **Base Unloader: `lastTags` is per-save, not per-session** (`Core.lua:168-171`), shared across split-screen players and offered weeks later; and `noteTags` after a toggle off remembers "what was left", not the set the player composed.
