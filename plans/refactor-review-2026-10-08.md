# Codebase refactoring review, 2026-10-08

Scope: every Lua file under `DanTraits/42/media/lua` (16,000 lines, 53 shared files, 6 client, 4 timed actions, distributions) and the offline tests. Branch `age-v2` at dc23bc4 plus the working tree. Baseline before any change: `python tests/run_tests.py` passes lint, the API check and all 67 tests.

## Verdict

The architecture is sound and most of it is already shared: one driver scheduler with a written-down order, a named value-hook registry, the stat delta pipeline, pain floors, `DanTraits_Wrap`, the moodle updater, the Util globals aliased into locals, and a stub harness with a test per file. The refactoring left is of two kinds. First, the older files were written before some of that infrastructure existed and still carry their own copy of it. Second, a handful of mechanisms exist once each in core but the trait files bypass them. Nothing here is a rewrite. Every item below is a helper that replaces N copies, a table that replaces N declarations, or a long function split at a seam the tests already pin.

Items are grouped by tier and ranked within each tier by value divided by risk. Line numbers are from today's working tree.

## Tier 1: behaviour fixes dressed as refactors (do first, small)

1. **Concussion and WoundCare do not stand down when their option is turned off mid-game.** `DanTraits_Concussion.lua:270` returns early, leaving `ccScore`, `ccTier` and the moodle in place, and `DanTraits_ConcussionStrength` (`:103`) keeps feeding Migraine, Epilepsy and Hallucinations. WoundCare (`:316`) leaves `wcParts`, so `DanTraits_PoorStitches` still says true. Blood (`:217`) and Infection (`:281`) have a `standDown`. Add the same to both, and have the strength getters check the option. Add a "switched off mid-concussion" test modelled on `test_infection.lua:200-208`.

2. **The hook primitives swallow errors with no log line.** `runDrivers` prints a failing system once; `DanTraits_RunHooks` (`DanTraits.lua:259`), `DanTraits_Later` (`:274`), `DanTraits_OnEat` (`:418`), `DanTraits_Story` (`:67`) and `DanTraits_MoodleLevels` (`Moodles.lua:186`) pcall silently. A typo in any `AddHook` body makes the hook return nil and the tests pass on the unadjusted value. Shape: `DanTraits_Guard(tag, fn, ...)` that pcalls, prints once per tag through the existing `driverFailed` table, and re-raises when `DanTraits_STRICT` is set; the harness sets STRICT in `H.stubs()`. Expect STRICT to surface something on first run. That is the point.

3. **Outer pcalls around pure Lua hide test failures.** The worst three: `DanTraits_Diabetes.lua:529-557` wraps the whole symptom block in one pcall, so a nil tier index cancels every symptom every minute with no line in the log; `DanTraits_Migraine.lua:309-321` puts thirst, stress and five getters in one pcall, so one erroring getter zeroes seven triggers; `DanTraits_Hangover.lua:155-166` wraps PainFloor and four StatAdds together. Smaller: `Blood.lua:143,245`, `Concussion.lua:225,302`, `WoundCare.lua:158,244`, `Vitality.lua:335,383`, `Sleep.lua:205`, `StraightEdge.lua:63`, `Anemia.lua:334`, `AgeTraits.lua:460`, `Hallucinations.lua:97,212`. Rule: pcall only a direct game-object call, never a `DanTraits_*` function that is documented as never throwing. Keep the pcalls around `DanTraits_FloorUp`: its `stats:get` is unguarded.

## Tier 2: one helper replaces N copies (mechanical, low risk)

4. **`DanTraits_SetTrait(player, ref, on)`.** Nine hand-rolled copies of "getCharacterTraits, add or remove in pcall, TraitsChanged": `DanTraits.lua:170` (RetireTraits), `Util.lua:529` (GrantFoldIn), `Age.lua:277`, `Dependent.lua:73`, `Hemophobia.lua:117`, `Migraine.lua:289`, `Smoker.lua:139`, `Tinnitus.lua:36`, `Telemetry.lua:348`. Two check `traits:get` first, the rest do not; some skip `TraitsChanged`. `ref` is a mod key or `"base:CONST"`, resolved the way RetireTraits already does (`:174`). Tests: core retire, steadyhands, positives, alcoholic, hemophobia, tinnitus, smoker, migraine, telemetry.

5. **`DanTraits_DRINK` moves to Util; four dead fallback copies go.** `Dependent.lua:27`, `Diabetes.lua:12`, `Hangover.lua:28`, `MDD.lua:7` each restate `{ any, tipsy, buzz, sober }` behind `DanTraits_DRINK or`. Shared files load alphabetically so Alcohol (`:69`) always wins and the copies only ever run in tests that skip Alcohol, yet each will diverge silently the day a threshold moves. Diabetes and MDD also copy `intoxOf`. Same class of borrowed constant: `Dependent.lua:43-45` DEP_SATED_MIN/MAX are Alcohol's drunk levels 1 and 2 on the 0..1 scale; `Spoons.lua:52,77-80` and `Migraine.lua:96-97` carry Sleep's and Vitality's night numbers by hand; `Smoker.lua:115` COUGH_RADIUS 35 duplicates Util's game-cough radius (pass nil).

6. **`DanTraits_Strength(name, player)`.** The "read another system's 0..1" boilerplate (guard the global, pcall, tonumber, clamp) is written out in `Epilepsy.lua:83-89` six times, `Migraine.lua:316-320`, `Hallucinations.lua:424-439`, `MS.lua:261-264`, `Heart.lua:96-100`, `Asthma.lua:183`, `Diabetes.lua:514`, `Sleep.lua:205`. One Util function, string-named so the global is resolved at call time as the guards do now. This also fixes the Migraine single-pcall problem in item 3.

7. **`DanTraits_StartingKit(player, spec)`.** The create-player handler is copy-pasted in Heart `:227`, Epilepsy `:204`, Asthma `:294`, Migraine `:523`, MS `:451`, Arthritis `:293`, Diabetes `:580`, PillCaddy `:51`: trait check, `xKitGiven` flag, `getHoursSurvived() > 0` gate, `MedStart`, `StartingMedication` check, AddItem loop. Spec per file: `{ trait, flag, meds = {...}, items = {...}, always = {...}, prepare = fn(item) }`. Diabetes is the odd one (`always` = meter and strips regardless of the option, items chosen by type), Arthritis and Migraine need `prepare` (DanTraitsFilled, the two-tablet pack). Register the one OnCreatePlayer handler after core's migrate and retire handlers. Each file's existing kit test fires OnCreatePlayer twice and with the option off, so coverage is already there.

8. **Let the drug registry announce the lapse.** `Heart.lua:150-154,197-214` and `Epilepsy.lua:139-143,169-191` hand-roll the wearing-off notice with `hcCovered`/`epCovered`, while Meds already does this for prednisone, baclofen and amantadine through `lapse`/`lapseTrait` (`Meds.lua:358-382`, and its header at `:32-33` notes the exception). Add the two keys to `beta` and `anticonvulsant`, delete the two notice functions, two mod-data keys and Epilepsy's pill hook. The notice moves from order 40 to Meds' order 30 in the same minute; check `test_heart` 6 and `test_epilepsy` 2 do not read the old keys directly.

9. **`DanTraits_DropHeld(player, bothHands, textKey)`.** `Arthritis.lua:191-202` drops the primary hand only, unguarded; `MS.lua:173-194` drops both hands, guarded. Epilepsy `:126` and Dependent `:109` call the Arthritis one, so an inventory error there propagates into OnWeaponSwing. Tests: arthritis 7-8, ms 4, epilepsy 3, alcoholic.

10. **Small Util additions, each replacing three or more copies.** `DanTraits_PartLodged(part)` for `haveGlass or haveBullet` (`Blood.lua:150`, `Clotting.lua:44`, `Infection.lua:128`, `Positives.lua:192`). `DanTraits_EachPart(player, fn)` with a pcall per part instead of one around the whole loop, which today skips every remaining part on one bad read (eleven loops: Blood, WoundCare, Infection, Hemophilia, Faint, Knox, Positives, Germaphobe, BadDay, Age). `DanTraits_MoodleLevel(player, moodle, stat, tiers)` for "moodle level, else tier the stat" (`Alcohol.lua:53`, `Dehydration.lua:37`, `Anger.lua:50`; Alcohol uses strict greater-than, the others greater-or-equal, pick one). `DanTraits_SandboxNum(option, default)` beside `SandboxOn` for the six hand-rolled number reads (`Meds.lua:211`, `MS.lua:146`, `Knox.lua:21`, `Age.lua:145`, `Distributions.lua:341`, `Client.lua:262`). Inline tier loops that are `DanTraits_TierOf` (`Concussion.lua:290`, `Dehydration.lua:45,51`, `Hangover.lua:81`, `Vitality.lua:322`, `Asthma.lua:89`); `Knox.lua:33-41` reimplements `DanTraits_StatFraction`; `Asthma.lua:287` reimplements `DanTraits_IsItem`.

## Tier 3: one source of truth

11. **One XP pipeline instead of three AddXP handlers.** `Age.lua:391-422`, `AgeTraits.lua:120-152` and `Vitality.lua:444-454` each register on `Events.AddXP` with their own re-entry flag and their own `inList`. Age and AgeTraits each add `amount * (k - 1)` to the original gain, so across files the factors add, not multiply, which contradicts the comment at `Age.lua:398` and the docs. Vitality's top-up re-fires the event and Age scales it again, so 20s plus Thriving happens to come out as a product while 20s plus Quick Study comes out as a sum. Shape: Age keeps the one handler and runs `k = DanTraits_RunHooks("xpFactor", 1, player, perk, level)`; AgeTraits and Vitality register `xpFactor` hooks returning `k * theirs`. Numbers shift for stacked characters (20s + Quick Study under level 3: x1.6 to x1.68; with Thriving on Fitness: 2.85 to 3.15), so decide first whether the product is wanted, then update docs/age.md and the field guide. Write the stacking tests before touching it: today `test_agetraits.lua` never loads Age or Vitality and `test_age.lua` never loads AgeTraits, so no test covers any combination.

12. **Age band data declared once.** `Age.lua:103-104` (`AGE_TRAIT`, `AGE_BANDS`), `Client.lua:268,298,467` (`AGE_BAND_OF`, `AGE_KEYS`, the literal `"AgeBonus20s".."50s"` list) and `Age.lua:145-149`. Export the two tables from Age; Client derives its maps. Fold the ten one-line hook registrations at `Age.lua:317-325,337-339` into `AGE_SCALES = { enduranceRegen = "endurance", woundHeal = "heal", ... }` and one loop, so the AGE table is the only place a multiplier lives, as its header promises. Put the live-versus-saved sandbox read (`ageOption` in Client, `sandbox()` in Age) in Util as `DanTraits_SandboxLive`.

13. **Core should not name trait-file globals.** `DanTraits.lua:418-427` calls `DanTraits_MddOnEat`, `DiaOnEat`, `VitalityOnEat` and `GlutenOnEat` behind `if X then` guards around the `"eat"` hook; `:434-438` guards `DanTraits_RefuseReason` (defined in Vegetarian); `:484` special-cases `DanTraits_MddOnPill` before the `"pill"` hook. Each file should register an `"eat"`, `"refuse"` or `"pill"` hook instead. Order changes from fixed to load order; check none of the four eat readers depends on another's write in the same call before switching.

14. **The drug registry is one table of behaviour and six tables of identity.** `Meds.lua:63-182` keys drugs by lower-case item type; `:506-510` SPAWN_TYPES and `:477-483` VANILLA_ITEMS are separate lists; full-type constants are repeated in Diabetes `:99`, Epilepsy `:63`, Smoker `:95`, Sunburn `:70`, Migraine `:142`, MS `:421`, Anemia `:136`, Asthma `:286`; Distributions and PillCaddy have their own. Adding a bottle touches five places and SPAWN_TYPES already lags (no MS bottles, by design, but nothing in Meds says so). Shape: `DanTraits_Drugs.x.item` is the full type, `spawnFill = true` per drug, SPAWN_TYPES and `byItem` derived, trait files read `DanTraits_Drugs.x.item` after `require "DanTraits_Meds"` as PillCaddy already does. Also route the mod's own `UseDelta` decimals (0.0333, 0.1666) through the `%.4f` formatter Meds uses for vanilla's bottles. Leave Distributions' weights alone: loot config, not identity.

15. **Spoons owns its count.** The default 12 is in `MS.lua:123`, `Spoons.lua:50` and the sandbox file; MS reads the sandbox itself (`:144-150`), its `spoonCap` hook replaces the cap wholesale (`:363-368`) and its console prints Spoons' keys (`:438-443`). Spoons exports `DanTraits_SpoonCount()` and `DanTraits_SpoonsOn()`; MS's hook becomes "in a flare, cap times MS_SPOON_FLARE"; the spoons console line moves to Spoons.

16. **One route for "a dose was taken".** The vanilla pill wrap and `ISVitalityPillAction` fire `prePill`/`pill`; `ISUseInhalerAction.lua:128-134` calls `DanTraits_UseInhaler` then `DanTraits_MedTake` by hand; `ISDiabetesAction.lua:73-76`'s pill kind calls `DanTraits_DiaOnPill` with no hooks. Inhaler and metformin can become `ISVitalityPillAction` with `"pill"` hooks keyed on the drug, the way Epilepsy (`:186`) and Anemia already do; delete `ISUseInhalerAction`. Watch for double dosing: Meds' pill hook does MedTake, so the manual call must go.

17. **`DanTraits_Wrap` re-applies itself.** Fifteen files do `wrapX(); Events.OnGameStart.Add(wrapX)` (core `:468,490`, AgeTraits `:483`, Alcohol `:122`, Anger `:143`, Diabetes `:633`, Hemophobia `:101`, MS `:412`, Positives `:156`, SteadyHands `:81,116`, StraightEdge `:75`, WoundCare `:367,387`, ClotMenu `:77`). Wrap is already idempotent by tag; let it record what it installed and have one core OnGameStart handler re-apply any wrap another mod replaced. Keep a deferred form for classes that are nil at load.

18. **Client's six copy-pasted pill context menus** (`Client.lua:149-240`: iron, gum, anticonvulsant, MS, sunblock, inhaler, each its own `OnFillInventoryObjectContextMenu` handler) become one `PILL_MENUS` table and one handler.

## Not worth doing

Consolidated from the four reviewers, so these do not get chased later.

- The `local hasTrait = DanTraits_HasTrait` alias blocks and the per-file `xData(player)` defaulting helpers: house style, and they keep files under the local and upvalue limits.
- One `enduranceRegen` hook per file: that is the delta pipeline's design.
- The `sandboxOn()` one-liners per file: each bakes in its own option name.
- `Food.lua` wrappers (`IsWheat`, `IsDairy`, `IsMeat`): one classifier already; the wrappers are the names callers use. Caffeine's and Lactose's fluid lists are fluids, which the classifier deliberately leaves out.
- `inList` in Age and AgeTraits, `today()` in Meds and AgeTraits: three-line locals (they disappear with item 11 anyway).
- Direct `player:getModData().DanTraits` reads (about 45): deliberate read-without-create, Telemetry `:189` explains why.
- `gameMinute` in core and Attrib: Attrib loads first and must not depend on core.
- `DanTraits_RETIRED` and the retired ids in the script and translations: save compatibility.
- Telemetry's and ISDiabetesAction's `if DanTraits_X` guards: a debug tool and a client-loaded file must work with any subset loaded.
- Meds' `migrate(d)` on every read: five nil checks, the comment explains why not once.
- MS `setFloors` versus Arthritis' stiffness loop, Heart exertion versus Asthma spending, Migraine `heatOf` versus MS `heatTarget`, Blood's versus Infection's `standDown`: same shape, different semantics.
- Client's `professionBoosts` versus Age's: different sources (the screen versus the descriptor), same transform call.
- Spoons as its own file: correct, it is a pool with registered users.
- Globals exported for the tests and the dashboard (`Drivers`, `Hooks`, `DeltaKeys`, `MedPatchScripts`, `AttribState`): the headers state the convention.
