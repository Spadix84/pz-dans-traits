# Documentation, the Guide hook and the modder APIs (2026-11-07)

Agreed on 2026-11-07 after a review of everything since the 1.5.1 upload. 1.5.2 is
committed (ec5221f) and **not uploaded**; it may still grow, so everything here lands
under the 1.5.2 header and nothing becomes 1.5.3. The in-game script for the catchable
illnesses (`illness-tests-2026-11-04.md`, 49 checks) has not been run, so 1.5.2 is not
ready to upload whatever this plan finishes.

## What the review found

- Uncommitted and sound: the reload-crash guard (`DanTraits_ReloadGuard.lua`), the Blood
  frame trim (Wound Damage off), the Slow Cooker home-cooking hook in Vitality, the
  harness rebuilding the frame set before every `H.frame`. 115 of 115 offline tests pass.
  The Slow Cooker hook was in neither changelog.
- Stale: the README said 1.5.0 and still asked for "illnesses without a trait"; Base
  Unloader was "not yet play-tested"; only Base Unloader had a README section at all.
- Over-claiming: the Guide's companion-mods page said five mods "each on the Workshop on
  its own". Published: Vitality (3811016852) and Map Legend (3831306437). Not published:
  Dan's Vanilla Fixes, Base Unloader, Vitality Cartridges, Vitality Challenges, Slow Cooker.
- The Workshop page linked none of the user's other mods (Map Legend's page links back).
  It sits at 7815 characters + 67 line breaks = 7882 of Steam's 8000.
- Slow Cooker (`../pz-slow-cooker`) is not under git. Its Workshop page cannot link to
  source until it is. Decision pending: its own repository (recommended; it has its own
  tooling and art pipeline) or this one.

## Decisions

- Workshop links name **published mods only**: Map Legend now, Slow Cooker once it has an
  id, the other four as they go up.
- The test files stay **untracked**, as before (the harness and the existing tests'
  edits stay unstaged too).
- The companion mods add to the Guide **without depending on it**: a global table.
- The modder API follows the Slow Cooker's: a `*_API.lua` with `API_VERSION`, loaded by
  `pcall(require, ...)`, and an `API.md` shipped in the mod folder.

## The pieces

### 1. The Guide hook (`client/DanTraits_Guide.lua`, `client/DanTraits_GuideData.lua`)

- `DanTraits_GuideExtra`: a plain global list. Another mod does
  `DanTraits_GuideExtra = DanTraits_GuideExtra or {}` and inserts
  `{ id, title, body, order?, picture?, mod? }`. Nothing to require, nothing to check;
  without Vitality the table sits unused. `DanTraits_GuideAddPage(page)` does the same
  with the checks up front and replaces a page of the same id.
- The extras sit after this mod's pages (order, then title) and before What's New. The
  picture is `page.picture` or `media/ui/Guide/<id>.png`; the game looks textures up across
  every loaded mod's media, so a companion ships its own.
- The companion-mods page is built when the window opens from
  `DanTraits_GuideData.companions`: each mod's blurb and a line saying Installed (and that
  its own page is further down when it registered one), On the Workshop, or Not yet on
  the Workshop. It can never over-claim again. Slow Cooker is on it.

### 2. A Guide page in each companion

One client file per mod (`<Mod>_Guide.lua`), overview and need-to-know in the Guide's
voice: Dan's Vanilla Fixes, Base Unloader, Map Legend, Vitality Cartridges, Vitality
Challenges, and Slow Cooker in its own repository.

### 3. The Vitality API (`shared/DanTraits_API.lua`, `DanTraits/API.md`)

`VitalityProject` (global), `API_VERSION = 1`. Thin, guarded wrappers over the seams the
companion mods and the Slow Cooker already lean on, frozen; everything else stays
internal and may change:

- traits: `hasTrait(player, id)`, the trait ids
- clocks and lifecycle: `every(cadence, label, fn, order, opts)`, `onPlayerReady(label, fn)`
- value hooks: `addHook(name, fn, order)` with the documented names (eat, drink, pill,
  prePill, nightQuality, sleepWake, enduranceRegen, infectionHazard, infectionGrowth,
  woundHeal, foodGrade, hungerRise, fatigueRise, boredomRise, panicRise, catchCold,
  strainRelief, refuseFood), `runHooks` for a mod's own names
- `wrap(class, method, tag, fn)`
- notices: `notify(player, textKey, good, ...)`, `story(player, kind, text, tone)` and the
  `OnStoryEvent` Lua event
- the body: `knockHead(player, chance, score)`, `passOut(player, minutes, textKey)`,
  `painFloor(player, source, floor, ramp, hold)`, `bloodState(player)`
- living: `vitalityTier(player)`, `vitalityEffect(player)`, `homeCooked(item)` and the
  `slowCookerHome` / `slowCookerDish` mod-data marks, `foodTags(item)`
- burnout: `burnout(player)`, `comfort(player, kind, amount)`, `strainAdd` / `strainEase`
- illness and fever: `illness(player)`, `catchIllness(player, id, now)`, `fever(player)`,
  `feverSource(name, fn)`, `relief(player, kind)`
- the guide: `guidePage(page)`
- `data(player)`: the per-player table, read-only, keys not promised

### 4. The Map Legend API (`shared/MapLegend_API.lua`, `MapLegend/API.md`)

`MapLegend.API_VERSION = 1`: `addPreset(name, text)`, `entries(player)`,
`meaning(player, sym, r, g, b)`, `forSymbol(player, sym)`, `put(player, sym, r, g, b, text)`,
`remove(player, sym, r, g, b)`, `isOwn` / `setOwn`, `on("changed", fn)` / `off`, the pens
rule (any pen a mod adds to the symbols panel is picked up).

### 5. GitHub

- `README.md`: a mods table near the top (what each does, Workshop link or status,
  folder), version 1.5.2, Status and Requests brought up to date, the Base Unloader line
  fixed, the API linked.
- A short `README.md` in each companion folder, for the Workshop "Source on GitHub" link.
- `CHANGELOG.md` and `workshop/changelog.txt`: Unreleased folded into 1.5.2 with the
  Slow Cooker hook, the Guide hook, the APIs and the companion pages added; What's New
  gains the same lines.

### 6. The Workshop pages

- Vitality: a "More from the same project" block (Map Legend; Slow Cooker when it has
  an id), the FAQ's supported-mods line names the Slow Cooker, trimmed elsewhere to stay
  under 8000 as Steam counts.
- Map Legend: the same block.
- `workshop/steam_desc.py`: counts a description as Steam does (characters + 2 per line
  break) and rebuilds `workshop.txt`'s description lines from `description.txt`, so the
  two cannot drift and an upload never fails at the limit again.
